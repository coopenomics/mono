# api-tests — внешний слой тестов

Тесты разговаривают с платформой только через её API на поднятом стенде — как
рабочий стол пайщика или посторонний клиент. Они не знают ни языка сервера, ни
его ORM, поэтому страхуют уход с TypeORM на Kysely (C28-81) и любую смену
бэкенда: пока слой зелёный, поведение не изменилось. Юнит-тесты контроллера
остаются — они проверяют правила изнутри, этот слой проверяет, что правила
доходят до клиента.

Прежние наборы живут в `components/boot/src/tests`; новое пишется здесь, на
общем каркасе.

## Где гоняется

Только на стенде. Полигон — ветка `ci/blackbox` на GitHub-зеркале
(`.github/workflows/blackbox.yaml`, `scripts/blackbox/stack.sh`): фаза
`apitests` гоняет всё, кроме матрицы прав, фаза `rights` — матрицу прав
последней. Локально на машине разработчика не запускать (CLAUDE.md).

## Каркас (`src/core`)

| модуль | что даёт |
|---|---|
| `client` | `gql` (бросает `ApiError` с кодами сервера), `gqlRaw`, `gqlError` — только Bearer, без `server-secret` |
| `auth` | `login(who)` — вход подписью, как SDK; `tokenOf(who)` — токен из кеша прогона |
| `roles` | `CHAIRMAN`, `COUNCIL`, `ROLES.*` — готовые участники стенда по ролям |
| `participants` | `freshMember()` — новый пайщик с собственным ключом |
| `chain` | `transact(who, actions)` с уникальным сроком действия, `tableRows`, `chainMessage` |
| `wait` | `waitFor(probe)` — ожидание зеркала после записи в цепь мимо контроллера |

## Правила

1. **Проверяемое — через API.** Готовить состояние можно чем угодно (сид,
   прямое действие в цепь), проверять — только тем, что видит клиент.
2. **Общих участников не портить.** Меняешь состояние пайщика — бери
   `freshMember()`. Роли из `ROLES` — для проверок прав и чтения.
3. **После мутации контроллера не ждать.** Транзакция отвечает, когда узел
   разобрал её блок. `waitFor` — только после записи в цепь мимо контроллера.
4. **Случай реестра в имени теста** — `it(caseName('mkt.order.side.40', '…'))`,
   а файл теста — в поле `api` случая (`test-registry/*.yaml`). Храповик
   `scripts/check-registry-external.mjs` не даёт долгу внешнего слоя расти.
5. **Прав контракт и стандарт.** Тест, подогнанный под текущее поведение,
   делает баг нормой: спорное — вопросом владельцу, не ассертом.
6. **Отказ проверяется кодом.** Права — `KIT_INSUFFICIENT_RIGHTS`, `401`,
   `403`, `MARKETPLACE_*`; доменные отказы — их собственным кодом, а не
   текстом.

## Матрица прав (`src/rights`)

Каждая операция схемы вызывается от лица каждой роли с заведомо чужими
аргументами; ответ классифицируется: отказ по входу, отказ по роли, прошло
проверку прав. Итог сверяется с утверждённым снимком — новая операция без
проверки прав или ослабленная проверка роняет прогон.

## Покрытие таблиц

Во время прогона Postgres ведёт журнал запросов; `scripts/blackbox/db-coverage.mjs`
сводит, какие таблицы внешний слой читал и писал, по доменам. Таблица, которую
никто не трогает, — первая кандидатура на новый тест перед переводом её
репозитория на Kysely.

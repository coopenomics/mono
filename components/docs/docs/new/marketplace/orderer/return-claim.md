# Гарантийный возврат имущества (orderer-стол)

Раздел `/<coopname>/market/returns` (Story 7.1) — единая точка работы
пайщика с гарантийными возвратами по полученным заказам. Здесь и подаётся
новое заявление, и отслеживаются активные, и хранится архив закрытых.
Заявление о возврате — это документ реестра `registry_id=1104`,
доступ через access-matrix marketplace ограничен ролью `ReturnClaim:
['create:own', 'read:own']` (фильтр по `orderer_account`).

## 1. Условие подачи заявления

Под заголовком — серая пояснительная строка:

> Подача заявления возможна только по выданному заказу в пределах
> гарантийного срока, заданного поставщиком.

Это критичное правило. Заявление можно подать только если:

- Заказ уже **получен** (статус `RECEIVED` — пайщик расписался на ПВЗ);
- **Гарантийный срок ещё не истёк** (срок задаётся поставщиком в карточке
  Предложения; backend сверяет дату подачи заявления с
  `actual_delivered_at + warranty_period`);
- Это заявление подаётся **самим заказчиком**, не от чужого имени.

При нарушении любого условия backend отклонит мутацию `submitReturnClaim`
с конкретным сообщением — UI покажет ошибку поверх формы.

## 2. Форма подачи заявления

Заголовок формы скрыт, но видна одна строка:

- **Поле «Идентификатор полученного заказа»** — текстовый ввод с
  placeholder'ом. Сюда пайщик вставляет идентификатор своего заказа
  из списка [Получены][orders] (раздел «Мои заказы», таб «Получены»).
- **Кнопка «📋 Подать заявление»** (primary, зелёная) — открывает
  диалог `SubmitReturnClaimDialog` с дополнительными полями
  (`reason_text`, `defect_category`, `actual_quantity`, фото) и
  собирает hash документа 1104 для подписи ЭП пайщика.

!!!warning "Подпись — обязательна"
    Заявление возврата подписывается ЭП заказчика. Без подписи backend
    отклонит мутацию: документ 1104 в реестре `documents` без подписи
    невалиден. Сценарий подписания идентичен прочим документам кооператива
    (см. раздел «Электронная подпись»).

## 3. Активные заявления

Блок **«Активные заявления»** — отдельная карточка под формой. Здесь
будут заявления в статусах «подано», «приглашён на очный осмотр»,
«рассматривается удалённо», «принято к возврату» — то есть все,
по которым решение председателя КУ ещё не зафиксировано окончательно.

В пустом состоянии (на скриншоте) карточка показывает только текст
**«Нет активных заявлений на возврат.»**

## 4. Архив заявлений

Блок **«Архив заявлений»** — закрытые заявления: одобренные с
возвратом средств, отклонённые, отозванные. Сюда заявление попадает
после финального решения председателя КУ (Story 7.2-7.4 — operator-стол
гарантийных возвратов).

В пустом состоянии — **«Архив пуст.»**

!!!info "Откуда возьмутся данные"
    `ReturnClaim` хранится в backend (PostgreSQL `marketplace_return_claims`)
    и читается двумя GraphQL-запросами: активные и архивные.
    Live-обновления — polling, как и у «Моих заказов» (Subscription
    в kernel pubsub — отдельная история Эпика 9).

## Откуда пайщик сюда попадает

Через прямой URL `/<coopname>/market/returns` или из карточки получённого
заказа в «Моих заказах» — кнопка «Оформить возврат» (если гарантийный
срок ещё не вышел).

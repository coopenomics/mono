# Закрывающая подпись акта приёмки

!!!warning "Эпик 6 — в разработке"
    Отдельная страница «Акты на закрывающую подпись» для председателя КУ ещё не выделена в UI: пока используется общая лента подписаний председателя. Описание ниже отражает целевое UX, которое появится после завершения Эпика 6.

Председатель кооперативного участка ставит **закрывающую подпись** акта приёма-передачи. Без неё имущество не считается принятым на баланс кооператива.

## Когда нужно подписывать

В ленте «Акты на закрывающую подпись» появляется акт, у которого:

- Оператор уже сформировал документ с фактическим количеством по каждому Заказу.
- **Поставщик уже поставил первую подпись** (либо лично на стойке в Варианте А, либо удалённо через push в Варианте Б).
- Акт в статусе **PENDING_CHAIRMAN_RECEPTION_SIGN**.

Председатель — это **второй подписант**, последний в цепочке. После его подписи акт закрыт.

## Что председатель видит

Открыв акт, председатель видит:

- Все реквизиты: партия, поставщик, имущество, ПВЗ.
- **Подпись поставщика** — кто подписал, когда, с указанием способа (личная / удалённая).
- **Список Заказов** с заказанным и фактическим количеством.
- **Расхождения** (если есть) — отдельной таблицей: какие Заказы недополучены, какие повреждены.
- Подпись оператора (как составителя акта).

## Решение

Председатель должен убедиться, что:

1. **Состояние имущества соответствует фактическим записям** — он может пройти по складу и проверить лично, если есть сомнения.
2. **Расхождения с заказом обоснованы** — есть фотоматериалы (если поставщик через перевозчика), есть отметки оператора.
3. **Поставщик подписался на ту же версию акта** — backend проверит автоматически.

После проверки — нажать «Подписать акт». Председатель подписывает приватным ключом ЭП.

## Что произойдёт после подписи

В одной атомарной транзакции:

- Имущество переходит на баланс кооператива в реестре `inventory` участка (для каждой единицы создаётся запись).
- Сумма закупки списывается с программного кошелька каждого пайщика-заказчика на кооперативный накопитель.
- Запускается push-цепочка ко всем заказчикам: «Партия принята на ПВЗ, скоро будет готова к получению».
- Оператору приходит задача «Маркировать партию».

## Если председатель не согласен с актом

В MVP — председатель не может «отказаться» от акта в одном клике, потому что поставщик уже подписал. Возможные сценарии:

- Если расхождение с заказом критично — председатель связывается с поставщиком и оператором, дополнительный материальный осмотр; при подтверждённой проблеме акт пересоставляется (создаётся новый, старый отменяется).
- Если поставщик не идёт на контакт — председатель может выйти на совет с предложением о санкциях. В MVP это ручной процесс.

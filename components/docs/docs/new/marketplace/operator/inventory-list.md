# Склад моего кооперативного участка

Раздел `/<coopname>/market-pvz/warehouse` (Story 9.1) — рабочая таблица
**имущества на складе одного КУ** для председателя этого участка.
В отличие от сводного склада кооператива (где видна агрегация по всем
ПВЗ), здесь — поштучная таблица каждой маркированной единицы товара,
закреплённой за конкретным участком.

Доступ — `roles: ['chairman']`. Backend-правило в access-matrix marketplace:
**`Warehouse: ['read:own-KU']`** — председатель видит только свой участок;
обращение к чужому КУ backend отвергает.

## Форма-фильтр

В верхней части страницы — три поля и кнопка:

| Элемент                          | Назначение                                                                       |
|----------------------------------|----------------------------------------------------------------------------------|
| **Код кооперативного участка**   | ID КУ (`braname`). Без него лента не подгрузится — backend не угадывает.         |
| **Состояние** (выпадающий select)| Фильтр статуса единицы: `LABELED` / `ISSUED` / `RETURNED` / `WRITTEN_OFF`.       |
| **Заказчик** (свободный поиск)   | Поиск по аккаунту/имени пайщика, за которым закреплена единица.                  |
| **«Обновить»** (primary, зелёная)| Стартует GraphQL-запрос и заполняет таблицу.                                     |

## Таблица единиц имущества

Под формой — таблица с семью колонками:

| Колонка             | Что в ней                                                                       |
|---------------------|---------------------------------------------------------------------------------|
| **Штрих-код**       | Уникальный код, нанесённый на единицу при `o.mkt.label` (маркировка приёма).    |
| **Товар**           | Название позиции (SKU) и связанная карточка предложения.                         |
| **Заказчик**        | Аккаунт пайщика, за которым закреплена единица (если уже привязана к заказу).   |
| **Ед.**             | Единица измерения.                                                              |
| **Состояние**       | Текущий статус: `LABELED` (на складе, ждёт выдачи), `ISSUED` (выдан),           |
|                     | `RETURNED` (возвращён через гарантийный возврат), `WRITTEN_OFF` (списан).        |
| **Возраст**         | Сколько дней единица находится в текущем статусе — индикатор скоропорта.        |
| **Промаркировано ↓**| Дата/время маркировки. По умолчанию — первичная сортировка по убыванию.         |

В пустом состоянии (до нажатия «Обновить» или при пустом КУ):

> Введите код КУ и нажмите «Обновить».

## Жизненный цикл строки

Одна строка таблицы — это **одна единица имущества** в реестре
`marketplace_inventory`. Жизненный цикл строки соответствует движению
имущества:

1. **`LABELED`** — оператор принял партию и наклеил штрих-код
   (`o.mkt.label`, Story 6.2).
2. **`ISSUED`** — единица выдана пайщику через signiss2 (Story 6.6).
   Сюда же попадает заказчик в колонке «Заказчик».
3. **`RETURNED`** — пайщик подал заявление 1104, председатель КУ
   принял возврат (`o.mkt.return`, Story 7.2-7.4).
4. **`WRITTEN_OFF`** — списано через `o.mkt.wroff` после исполнения
   повестки совета (Story 8.7).

Каждый переход — отдельная ончейн-операция; backend marketplace
синхронизирует таблицу с этими событиями через listeners.

!!!info "Real-time без перезахода"
    Реал-тайм синхронизация через **AR37 SDK-подписки платформы**
    подключается отдельным шагом эпика. В MVP таблица обновляется
    после ручного нажатия «Обновить»; кратковременные изменения
    статуса могут не успеть отобразиться без рефреша.

## Зачем нужен «Возраст» отдельной колонкой

Колонка **«Возраст»** — индикатор скоропорта. Для скоропортящихся
товаров (пища, лекарства) председатель может фильтром «Состояние =
LABELED» + сортировкой по «Возраст ↓» быстро увидеть единицы,
которые на складе слишком долго и нужно подавать на списание
(см. [«Списания скоропорта»][writeoffs] на admin-столе).

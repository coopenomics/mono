# Выплаты поставщикам

!!!warning "Эпик 5 — в разработке"
    Read-only страница «Выплаты поставщикам» для совета ещё не реализована в UI. Поставщик уже видит свою историю выплат на [странице «История выплат»](../offerer/payments.md). Read-only агрегат по всему кооперативу для совета появится после завершения Эпика 5 / Story 5.x. Описание ниже отражает целевое поведение.

Совет имеет **read-only доступ** к ленте всех денежных выплат поставщикам — от подписи акта приёма-передачи до фактического перевода средств. Эта страница — финансовый контроль совета над основным потоком исходящих платежей.

## Что показывается

Каждая строка — **исходящий платёж** поставщику:

- **Поставщик** (ФИО, реквизиты счёта).
- **Партия / Предложение**, по которым идёт оплата.
- **Сумма** платежа (за вычетом комиссии кооператива).
- **Статус**:
    - `PENDING` — акт приёмки подписан, ждём финансиста / казначея на исполнение.
    - `SCHEDULED` — запланирован к выплате (например, в очередной банковский день).
    - `PAID` — деньги отправлены поставщику (банковский референс зафиксирован).
    - `FAILED` — не получилось перевести (неверные реквизиты и т. п.), требует ручного вмешательства.
- **Референс банка** (для статусов SCHEDULED / PAID).
- **Назначение платежа** — текст для банковского документа.
- **Дата создания** платежа и **дата исполнения** (если есть).

## Когда формируется платёж

Платёж возникает автоматически после **закрытия акта приёмки партии** (закрывающая подпись председателя участка):

- Backend рассчитывает сумму к выплате поставщику = `партия.total_amount - комиссия кооператива`.
- Создаётся запись в реестре исходящих платежей со статусом `PENDING`.
- Финансист кооператива (отдельная роль в столе председателя) запускает реальный банковский перевод и обновляет статус на `SCHEDULED` → `PAID`.

## Что видит совет

Совет смотрит на:

- **Общую сумму** выплат за период (день / неделя / месяц / год).
- **Распределение по поставщикам** — кому платим больше всего.
- **Среднее время от приёмки до выплаты** (важный SLA — поставщики должны получать оплату вовремя, иначе они уйдут из кооператива).
- **FAILED-платежи** — куда ушли деньги, и почему не дошли.

## Фильтры

- По статусу.
- По поставщику.
- По кооперативному участку (от какого ПВЗ шла партия).
- По диапазону сумм / дат.

## Действия совета

Совет не запускает выплаты вручную (это компетенция финансиста). Что доступно:

- **Открыть карточку платежа** — все детали + связанная партия / акт приёмки.
- **Открыть карточку поставщика** — портфель его Предложений и история платежей ему.
- **Заметка** — оставить пометку для следующего собрания совета (например, «обсудить задержку платежей в августе»).

## Зачем это нужно

Совет контролирует:

- **SLA выплат** — кооператив должен быть надёжным контрагентом для поставщиков.
- **Корректность сумм** — финансист правильно высчитал комиссию и не ошибся в реквизитах.
- **Отсутствие злоупотреблений** — нет ли подозрительных платежей в адрес поставщиков, аффилированных с кем-то из руководства.

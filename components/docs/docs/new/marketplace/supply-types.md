# Типы снабжения (отсечка заказов)

Каждое **Предложение** в Столе заказов несёт правило, по которому отдельные заказы пайщиков объединяются в **партию поставки** и по которому эта партия *стартует*. Это правило поставщик выбирает при публикации предложения в блоке **«Тип отсечки заказов»** — и оно одинаково важно обеим сторонам:

- **поставщику** — определяет, *когда* он начинает готовить отгрузку и сколько заказов соберётся в одну партию;
- **заказчику** — определяет, *сколько* он будет ждать с момента оформления заказа до выдачи и *в каких случаях* заказ может отмениться сам.

Типов четыре: **по расписанию**, **по объёму**, **открытая подписка** и **индивидуально**. Тип задаётся для каждого предложения отдельно — один поставщик может вести разные товары по разным правилам.

![Блок «Тип отсечки заказов» в форме создания предложения: четыре варианта-переключателя и подсказка под выбранным.](/assets/new/marketplace/offerer/offer-create/02-filled-form.png)

## Сравнение типов

| Тип | Кто запускает партию | Что поставщик задаёт | Что заказчик видит после оформления | Когда заказ отменяется сам |
|---|---|---|---|---|
| **Индивидуально** (`individual`) | Поставщик, по каждому заказу отдельно | Ничего дополнительно | «Ждёт поставщика» → дальше по потоку | Не отменяется по таймеру |
| **По объёму** (`volume_based`) | Система автоматически, когда наберётся объём | Целевой объём + макс. срок ожидания | «Ждёт цикла / решения», пока копится объём | Если за `N` дней объём не набрался |
| **Открытая подписка** (`open_subscription`) | Поставщик вручную, кнопкой «Запустить поставку» | Лимит ожидания пайщика (опц.) | «Ждёт цикла / решения» бессрочно | Заказчик может отменить сам после лимита ожидания |
| **По расписанию** (`time_based`) | Система по таймеру в конце цикла | Длительность цикла + мин. порог (опц.) | «Ждёт цикла / решения» до конца цикла | Если к концу цикла набралось меньше порога |

!!! info "Что значит «отсечка»"
    Отсечка — это момент, когда набранные заказы фиксируются в одну партию и уходят в работу: создаётся **сводная заявка**, поставщик принимает её, формирует партию и готовит отгрузку. До отсечки заказ «висит» в накоплении, а зарезервированные под него средства заказчика удерживаются на кошельке.

---

## Индивидуально (`individual`)

Самый простой и быстрый тип: партии и ожидания нет — каждый заказ обрабатывается сам по себе.

### Для поставщика

При выборе варианта **«Индивидуально (individual)»** дополнительных полей не появляется — подсказка формы поясняет: *«Принимаю каждый заказ индивидуально, без waiting»*. Каждый поступивший заказ приходит на стол **«Входящие заказы»** отдельной карточкой; поставщик принимает его кнопкой акцепта поштучно. Сразу после акцепта система автоматически формирует партию из одного этого заказа и переводит её в подготовку отгрузки — отдельно собирать группу не нужно.

Выбирайте этот тип для штучных или дорогих позиций, которые нет смысла копить в партию: каждый заказ едет своим ходом.

### Для заказчика

После оформления заказ сразу ждёт решения поставщика — в «Моих заказах» он отображается как **«Ждёт поставщика»**. Как только поставщик примет заказ, статус сменится на **«Принят поставщиком»**, и заказ пойдёт по обычному потоку: подготовка → приёмка на ПВЗ → готов к выдаче → получен. Ожидания «пока наберётся партия» здесь нет — это самый быстрый маршрут.

## По объёму (`volume_based`)

Партия стартует **автоматически**, как только суммарный объём заказов достигнет цели.

### Для поставщика

При выборе **«По объёму (volume_based)»** появляются два обязательных поля:

- **Целевой объём** — сколько единиц нужно накопить, чтобы партия стартовала;
- **Максимальный срок ожидания (дней)** — сколько ждать накопления, прежде чем отменить незавершённый цикл.

Подсказка формы: *«Поставка стартует когда наберётся объём; если за N дней не наберётся — заказы отменятся»*. Когда сумма количеств по активным заказам достигает целевого объёма, система **сама** закрывает цикл и формирует **сводную заявку** на всю партию — она приходит поставщику на стол **«Входящие заказы»** одной групповой карточкой. Поставщик принимает её целиком (одним действием на всю сводную заявку, а не по одному заказу).

Подходит для оптовых закупок, где поставка имеет смысл только от определённого объёма (мешок, паллета, минимальная партия).

### Для заказчика

Пока объём копится, заказ показывается как **«Ждёт цикла / решения»** — это нормальное состояние накопления, средства зарезервированы. Когда нужный объём наберётся (за счёт этого и чужих заказов по тому же предложению), цикл закроется и статус перейдёт в **«Ждёт поставщика»**, затем **«Принят поставщиком»** и дальше по потоку. Если за указанный поставщиком срок объём так и не набрался, заказ закрывается со статусом **«Цикл закрыт без объёма»**, а резерв средств снимается.

## Открытая подписка (`open_subscription`)

Бессрочный приём заказов: партию запускает **сам поставщик**, когда сочтёт нужным.

### Для поставщика

При выборе **«Открытая подписка (open_subscription)»** появляется одно необязательное поле — **«Лимит ожидания пайщика (дней, опц.)»**. Подсказка формы: *«Я сам нажму "Запустить поставку"; пайщики могут отменить, если ждут дольше N дней»*. Автоматической отсечки здесь нет: заказы копятся сколько угодно, пока поставщик не запустит поставку вручную. В момент запуска система разом фиксирует все накопленные заказы в одну сводную заявку и сразу принимает её — отдельно акцептовать не нужно.

Подходит для постоянного сбора под товар «по мере набора»: поставщик сам решает, достаточно ли заказов, чтобы везти.

!!! info "Где нажать «Запустить поставку»"
    Кнопка **«Запустить поставку»** находится на столе поставщика, в разделе **«Мои предложения»** — на карточке каждого опубликованного (статус *Опубликовано*) предложения с открытой подпиской. Перед запуском система просит подтверждение: действие необратимо. После подтверждения все накопленные заказы разом фиксируются в одну сводную заявку, которая сразу принимается, — отдельно акцептовать партию не нужно. Если по предложению ещё нет ни одного заказа, запуск отклоняется с пояснением «Пул заказов пуст — запускать нечего».

### Для заказчика

После оформления заказ остаётся в состоянии **«Ждёт цикла / решения»** без ограничения по времени — он попадёт в партию, когда поставщик запустит поставку. Если поставщик указал **лимит ожидания пайщика** и этот срок истёк, заказчик вправе **сам отменить** свой заказ (резерв средств при этом снимается). После запуска поставки заказ переходит в **«Принят поставщиком»** и идёт дальше по обычному потоку.

## По расписанию (`time_based`)

Партия стартует **по таймеру** — в конце заранее заданного цикла.

### Для поставщика

При выборе **«По расписанию (time_based)»** появляются:

- **Длительность цикла (дней)** — обязательное поле, через сколько дней цикл закроется (подсказка: *«Поставка по истечении цикла»*);
- **Минимальный порог объёма (опц.)** — необязательная защита от слишком мелкой партии (подсказка: *«Если к концу цикла набралось меньше — все заказы отменятся»*).

Подсказка типа: *«Поставка по истечении цикла; если набралось меньше — заказы отменятся»*. По завершении цикла система сама закрывает приём и формирует сводную заявку из накопленных заказов. Если задан минимальный порог и к концу цикла объём оказался ниже — партия не формируется, все заказы цикла отменяются.

Подходит для регулярных поставок с фиксированной периодичностью (например, недельный завоз).

### Для заказчика

Пока цикл идёт, заказ показывается как **«Ждёт цикла / решения»**. По завершении цикла (если набрался порог) заказ переходит в работу — **«Ждёт поставщика»** → **«Принят поставщиком»** и далее. Если к концу цикла минимальный порог не достигнут, заказ закрывается со статусом **«Цикл закрыт без минимального порога»**, а резерв снимается.

!!! note "Документировано по интерфейсу и логике"
    Тип «по расписанию» завязан на таймер закрытия цикла, поэтому его сквозной прогон не выполнялся вживую — описание построено по полям формы и логике закрытия цикла, общей с другими типами.

## Статусы заказа у заказчика

Независимо от типа отсечки, после старта партии заказ проходит общий маршрут. В разделе **«Мои заказы»** статусы отображаются так:

| Статус | Что означает |
|---|---|
| **Ждёт цикла / решения** | Заказ оформлен, идёт накопление партии (или ожидание решения поставщика) |
| **Ждёт поставщика** | Партия отсечена, сводная заявка ждёт акцепта поставщика |
| **Принят поставщиком** | Поставщик принял заявку, готовит отгрузку |
| **Поставка готовится** | Партия в подготовке к отгрузке |
| **Принят кооперативом** | Имущество принято на ПВЗ и переведено на баланс кооператива |
| **Готов к выдаче** | Имущество промаркировано, выдача открыта — можно забирать |
| **Получен** | Имущество выдано заказчику, заказ завершён |
| **Цикл закрыт без объёма** | `volume_based`: целевой объём не набрался за отведённый срок |
| **Цикл закрыт без минимального порога** | `time_based`: к концу цикла объём ниже минимального порога |
| **Отменён заказчиком / поставщиком** | Заказ отменён вручную одной из сторон |

!!! info "Резерв средств держится до выдачи"
    Во всех типах сумма заказа резервируется на кошельке заказчика в момент оформления и удерживается до выдачи имущества. При отмене или закрытии цикла без поставки резерв снимается обратно.

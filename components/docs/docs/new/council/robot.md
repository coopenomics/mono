# Робот совета

Робот совета принимает типовые решения совета автоматически, за секунды, по тем вопросам, которые члены совета заранее разрешили решать без личного участия. Он не подменяет совет: каждый голос и каждая подпись протокола остаются подписью конкретного члена совета. Их ставит ключ отдельного разрешения его аккаунта, выпущенного только для робота и ограниченного списком типов решений.

Стол «Робот совета» видят только члены совета. Председатель дополнительно управляет автоматической подписью протоколов и видит страницу состояния робота.

## Как устроено делегирование

1. Член совета на странице «Действия автоматизации» отмечает типы решений, по которым доверяет роботу свой голос, и нажимает «Сохранить настройки».
2. При первом сохранении на устройстве создаётся новый ключ. На аккаунте члена совета появляется отдельное разрешение «robot», привязанное только к голосованию в совете. Приватный ключ передаётся роботу по защищённому каналу и на устройстве не сохраняется. В блокчейн ключ не попадает.
3. Настройки записываются в реестр автоматизаций контракта совета: имя разрешения, типы решений для голосования, у председателя — типы решений, протоколы которых робот подписывает за него.
4. Контракт при каждом голосе и каждом утверждении проверяет, что ключ подписи принадлежит заявленному разрешению аккаунта члена совета и что тип решения делегирован. Подпись чужим ключом или по неделегированному типу отклоняется.

Отзыв делается кнопкой «Отозвать делегирование»: запись в реестре стирается, разрешение снимается с аккаунта, ключ удаляется у робота. После отзыва робот не может подписать ничего от имени этого члена совета, даже если копия ключа где-то осталась.

## Кворум робота

Решение принимается, когда «за» проголосовало больше половины состава совета. Робот доводит решение до протокола сам, только если делегировавших голоса членов совета с переданными ключами хватает для этого порога и председатель делегировал подпись протокола этого типа. Всё это видно в реестре по каждому типу решения:

- кто из членов совета делегировал голос и передал ли ключ;
- сколько голосов набирает робот и сколько нужно;
- подписывает ли протокол робот или председатель вручную.

Если кворума робота нет, робот голосует за тех, кто делегировал, а решение остаётся в повестке для ручного голосования. Протокол подписывается, когда кворум набран.

## Что делает робот с решением

1. Получает новую повестку делегированного типа и подаёт голоса от имени делегировавших одной транзакцией.
2. Дожидается, пока голоса лягут в блокчейн, и проверяет кворум.
3. Собирает протокол по шаблону этого типа решения, подписывает его ключом разрешения председателя и второй транзакцией утверждает и исполняет решение.

Каждый шаг записывается в журнал: этап, голоса, транзакции, ошибки. Сбой не теряется: робот повторяет попытку с растущей паузой, а после исчерпания попыток решение помечается как застрявшее и ждёт ручного повтора председателем на странице «Состояние робота».

## Пределы полномочий

- Робот не голосует и не подписывает по типам решений вне делегированного списка.
- Робот не имеет активных ключей членов совета и не хранит ключи в блокчейне.
- Ручной голос активным ключом принимается всегда, независимо от делегирования.
- Срок действия делегирования, если задан, проверяет контракт: просроченное делегирование не действует.

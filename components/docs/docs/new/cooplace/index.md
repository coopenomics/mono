
# Стол заказов (Cooplace)

## Что такое Cooplace

**Cooplace** — это бэкенд-модуль кооперативного маркетплейса и смарт-контракт, обеспечивающий полный цикл кооперативного обмена имуществом между пайщиками. Cooplace предоставляет API для управления карточками товаров, категориями, настройками, и обеспечивает взаимодействие с блокчейном при запуске поставок.

!!! info "Cooplace — бэкенд, Маркетплейс — фронтенд"
    **Cooplace** — это ядро: смарт-контракт + серверная логика (NestJS). Он не имеет собственного пользовательского интерфейса.
    
    **Маркетплейс** — это фронтенд-расширение (Vue), которое строит витрину, карточки товаров, процесс заказа поверх API Cooplace.
    
    Могут существовать и **другие** фронтенды к Cooplace: одностраничные магазины, мобильные приложения или вовсе отсутствие интерфейса (только API).

## Архитектура

```
┌─────────────────────┐
│  Маркетплейс (Vue)  │──── Фронтенд-расширение (витрина, заказы)
├─────────────────────┤
│  Другой сайт (Vue)  │──── Одностраничник для одного товара
├─────────────────────┤
│  Мобильное прил.    │──── Внешнее приложение
└────────┬────────────┘
         │ GraphQL API
┌────────▼────────────┐
│  Cooplace (NestJS)  │──── Бэкенд: карточки, категории, настройки, match, cycles
├─────────────────────┤
│  Blockchain (EOSIO) │──── Смарт-контракт: блокировка средств, поставка, возвраты
└─────────────────────┘
```

## Основные процессы

### 1. Жизненный цикл карточки

Карточка товара хранится в базе данных и проходит модерацию:

| Статус | Описание |
|--------|----------|
| `draft` | Черновик — редактируется автором |
| `moderation` | На модерации — ожидает одобрения |
| `published` | Опубликована — видна на витрине |
| `archived` | В архиве — снята с публикации |

### 2. Match и блокчейн

Каждая встречная заявка **сразу публикуется в блокчейн** — средства блокируются смарт-контрактом:

1. Карточка-предложение (`offer`) опубликована
2. Заказчик создаёт заказ (`order`) → **сразу в блокчейн** → средства заблокированы
3. Все последующие заказы → тоже сразу в блокчейн

!!! warning "Управление деньгами — дело смарт-контракта"
    Контроллер (NestJS) не блокирует и не разблокирует средства напрямую. Он только вызывает actions блокчейна. Это гарантирует, что средства не могут быть потеряны при сбое сервера.

### 3. Циклы поставки

Поставщик может указать минимальный объём и дедлайн:

- `min_units: 100` — минимум для запуска поставки
- `cycle_deadline: 2025-02-07` — крайний срок сбора заказов

Циклы **не влияют на match** — каждый заказ сразу в блокчейн. Циклы определяют:

- Когда поставщику **разрешено начать supply** (при наборе min_units)
- Когда цикл **истекает** → cancel всех заявок → возврат средств → новый цикл

### 4. Типы карточек

| Тип | Направление | Описание |
|-----|-------------|----------|
| `offer` | Поставщик → Заказчик | Обычное предложение на витрине |
| `order` | Заказчик → Поставщик | Запрос «поставьте мне» |

### 5. Типы доставки

| Тип | Описание |
|-----|----------|
| `internal` | Между кооперативными участками (внутренняя логистика) |
| `external` | Через внешний сервис (СДЭК, Почта России и т.д.) |

### 6. Типы взносов

| Тип | Описание |
|-----|----------|
| `share` | Паевой взнос — поставщик получает возврат паевого взноса |
| `member` | Членский взнос — кооператив покупает имущество у поставщика |

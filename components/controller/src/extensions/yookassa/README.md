# Оплата по ЮKassa — документация разработчика

Приложение принимает оплату взносов пайщиков через сервис ЮKassa. ЮKassa сообщает кооперативу об оплате, и платёж засчитывается автоматически.

Текст страницы в каталоге приложений — `CATALOG.md`: его читают председатель и совет, технических подробностей в нём нет. Этот файл — для разработчика.

## Запись реестра

Запись — в `components/controller/src/extensions/extensions.registry.ts`. Что значит каждое поле — корневой `components/controller/CLAUDE.md`, раздел «Что расширение объявляет о себе».

### `yookassa` — Оплата по ЮKassa

- Доступность в сети: вне основной сети (тестовая сеть и стенды); в основную сеть — отдельным решением.
- Ставится новому кооперативу сразу, выключенным (`defaults` в записи реестра).
- Модуль: `YookassaExtensionModule` — `yookassa/yookassa-extension.module.ts`.
- Своего рабочего стола нет: расширение работает на сервере и в чужих экранах.
- Поля настроек (`buildSchema` модуля, схему строит реестр при каждом обращении): `client`, `secret`, `ipn_url` (адрес уведомлений для кабинета ЮKassa: в основной сети только чтение), `fee_percent` (наибольшая комиссия).
- Миграции схемы базы: 0; миграции настроек: 0.
- Обязательные порты: `Logger`, `MessageChannel`, `PaymentNoticeLog`, `Payment`, `PaymentProviderRegistry`.

## Где что лежит

## Комиссия, способы оплаты, возврат

- Комиссию магазина ЮKassa до оплаты не сообщает, только после — в `income_amount`. Сумма к оплате считается от `fee_percent` — наибольшей комиссии по договору; поступило меньше суммы взноса — платёж отклоняется.
- Способы оплаты не ограничиваются: форма показывает способы, включённые в магазине. Ограничение формы (`customization.payment_methods`) ЮKassa разрешает магазину отдельно через менеджера; без разрешения форма не открывается с кодом `customization_of_payment_methods_not_allowed` (тестовый магазин, 24.11.2026). `payment_method_data` при `confirmation: embedded` ЮKassa отклоняет кодом 400. Набор способов кооператив согласует с менеджером в магазине. Способ, выбранный заранее, работает только со страницей ЮKassa (`confirmation: redirect`) — проверено на тестовом магазине, не сделано.
- Реквизиты платежа (`payment_details.data`) — объект `{ confirmation_token, payment_id }`; у платежей до 24.11.2026 — строка-токен.
- Возврат: кассир отклоняет входящий платёж, шлюз зовёт `refundPayment(hash)`. Платёж ЮKassa ищется по `payment_id`, у старых — по секрету кооператива в списке платежей за сутки. Возвращается вся оплаченная сумма; ключ идемпотентности `refund-<secret>`. Отказ ЮKassa — ошибка, платёж не отклоняется.
- Тесты: `tests/unit/gateway/yookassa-refund-fee.test.ts`, `tests/unit/gateway/yookassa-ipn-verify.test.ts`.
